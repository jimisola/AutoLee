# Codebase review — 2026-07-25

Point-in-time analysis produced by an independent Opus subagent reviewing branch `feat/esp-idf`
at commit `b31fe49` (it read the actual code — README, `docs/ARCHITECTURE.md`, `docs/PLAN.md`,
`main/`, `lib/autolee_logic/`, `api/` — not just the project description). A second pass
verified its central claims against the repo before anything here was acted on.

This is a snapshot, not a live source of truth — actionable items from it are tracked in
[`PLAN.md`](PLAN.md) Phase 4 (safety-critical, bench-blocking) and Phase 8 (post-migration
hardening). If this file and `PLAN.md` ever disagree on status, `PLAN.md` wins.

## Overall state

This is well past "port in progress" — it's a careful, mostly-finished ESP-IDF firmware with
better engineering hygiene than most hobby embedded repos: 9 Unity suites over 9 pure-logic
headers in `lib/autolee_logic/`, three-job CI with SHA-pinned actions, OpenAPI + AsyncAPI + JSON
Schema as a real contract, verified OTA rollback/coredump/watchdog, and a genuinely well-reasoned
concurrency design (`main/motion/motion_cmd.h` deferred-command layer, `sse_task` split out of
`pump_task`, `spi_device_acquire_bus()` around TMC transfers). `docs/PLAN.md` and
`docs/ARCHITECTURE.md` are unusually honest about what is and isn't hardware-verified. The
remaining gaps are not "missing features" — they're (a) two half-finished items the plan already
marked `[x]` (since corrected — see `PLAN.md` Phase 4), (b) zero persistence of machine state,
and (c) no automated coverage of the one file that actually matters for safety,
`main/motion/motion.cpp` (556 lines).

**Correction (added same day, after a follow-up review):** this review did not check whether
API/OTA authentication was implemented, and the "Re: Copilot's list" and roadmap-sequencing
sections below should not be read as saying it was missing. A later pass confirmed Digest auth
already gates every state-changing route (`main/net/web_server.cpp:271-300`) — see `PLAN.md`'s
`#1b`/`#1c` for the current, accurate status.

| 1 | **Persist machine settings + calibration to NVS (versioned blob)** | High | Med | `grep -rn 'nvs_' main/` hits only `wifi_mgr.cpp` (ssid/pass/AP key), `web_server.cpp` (webpass), `app_main.cpp` (init). Biggest real-user gap in the repo. |
| 2 | **Finish PLAN #8: snapshot the cross-task motion globals** | High | Med | PLAN.md marked "#8 + #2" done, but only #2 (command routing) actually shipped. `globals.h` still exports ~40 loose non-atomic `long`/`bool`; no `portMUX`/mutex exists anywhere in `main/` (atomics appear only in `stepper.cpp` and `motion_cmd.cpp`). `buildStateJSON()` (`web_server.cpp:66-107`) reads ~20 of them from the HTTP/SSE task while `pump_task` writes them mid-stroke. |
| 3 | **Route `handleMotion()` through `motor_fsm.h`** | High | Med | `motion.cpp` assigns `runState = …` directly in 12 places; `motorTransition`/`canStart` are never called (confirmed by grep). The exhaustively-tested "cannot Start from STALLED" rule is therefore tested but not enforced. `ARCHITECTURE.md` §4 already admits this. |
| 4 | **Dead/drifted watchdog config** | High | Low | `config.h`'s `ENABLE_TASK_WDT` and `TASK_WDT_TIMEOUT_MS = 8000` are read by nothing (grep → only their own definition). `sdkconfig.defaults` never sets `CONFIG_ESP_TASK_WDT_TIMEOUT_S`, so the real budget is the 5s default while the comment documents 8s — and `motion.cpp`'s blocking calibration/homing loops are sized against that comment. Set it explicitly, delete the dead constants. |
| 5 | **Fake stepper/TMC so motion.cpp is host-testable** | High | High | The pure logic is well covered, but the safety-critical *sequencing* (calibrate → hit → backoff → re-zero; jam → forceStop → backoff → STALLED; homing retries/timeouts) has zero automated coverage. `motion.cpp` already talks only to `stepper::` and `tmc5160::` namespaces — narrow seams, not a full HAL. Highest-value test investment left. |
| 6 | **`/api/v1/info` diagnostics endpoint** | Med | Low | No `esp_app_get_description()` anywhere; the only identity is `FW_VERSION "1.8"` in state JSON. Expose app-desc version/idf_ver/build date/elf SHA, `esp_reset_reason()`, free + min-ever heap, uptime, running partition, coredump-present flag. |
| 7 | **`LogRing` is not thread-safe** | Med | Low | `lib/autolee_logic/log_ring.h` has plain `head_`/`serial_`; `webLog()` is called from `pump_task` *and* HTTP handlers, while `sse_task` and `/api/v1/state` read concurrently. Corruption lands exactly on the jam/SG telemetry you'd be reading post-incident. |
| 8 | **Doc/config drift cleanup** | Med | Low | `FW_VERSION` still `"1.8"` for a `feat!` platform change (PLAN #24 open); `.pre-commit-config.yaml`'s exclude `^main/stepper_motor_encoder\.[ch]$` no longer matches after the move to `main/drivers/`, so vendored code may now be in or out of clang-format's scope unexpectedly. |
| 9 | **OTA image identity check** | Low | Low | `handleOtaUpload()` goes `esp_ota_begin/write/end/set_boot_partition` with no `esp_app_desc_t.project_name` check — a stray image boots and then rolls back. One `esp_ota_get_partition_description()` compare before `set_boot_partition`. |
| 10 | **SSE sends the full ~700B state doc every 250ms unconditionally** | Low | Low | `broadcastState()` rate-limits but never diffs. Send-on-change + a heartbeat cuts traffic and shrinks the stalled-client window the whole `sse_task` split exists to contain. |

**On the roadmap's sequencing:** the one reorder worth making is doing #2/#3/#5 above *before*
the bench session rather than during it — PLAN Phase 4 correctly demands "a safety-focused
review of the whole motion path before the first run," and torn state reads plus an untested
transition table are exactly what you don't want to be debugging with a live press.

## Re: a separate (README-only) Copilot review

A different AI produced a 13-item suggestion list without reading the code, working only from
the README. Comparing it against the actual repo:

1. **Migrate to ESP-IDF/components** — Already done; premise is wrong, this *is* native ESP-IDF. Splitting `main/` into `components/` would be churn (`main/CMakeLists.txt` already puts every subdir on `INCLUDE_DIRS`; `ARCHITECTURE.md` §5 says the grouping is navigational by choice).
2. **`esp_event` pub/sub everywhere** — Not applicable as framed; `motion_cmd`'s atomic-flag queue is *deliberately* the decoupling layer, guaranteeing only `pump_task` acts. A generic event bus would reintroduce the multi-task-touches-motion problem the design eliminates.
3. **One canonical state machine** — Already exists twice over (`RunState` in `globals.h`, tested table in `motor_fsm.h`); the real gap is item 3 above (not wired into `handleMotion()`), not that it's missing.
4. **Version your settings** — Still valid, folded into item 1 above (Med effort) — the actual problem is bigger: there are no persisted settings at all.
5. **Diagnostics endpoint** — Still valid, Low effort = item 6 above.
6. **Coredump via API** — Partly valid: coredump-to-flash is enabled and verified, but only retrievable over serial; a presence flag + reset reason (item 6) is the cheap 80%.
7. **`esp_app_desc`** — Still valid, Low effort, folded into item 6 above; grep confirms zero use today.
8. **Self-test page** — Mostly already done implicitly (`app_main.cpp` treats full init as the OTA validity check); a dedicated page is low value versus a bench-time SG-trace view.
9. **Health monitoring/cycle stats** — Low value until item 1 lands — nothing survives reboot today, so stats would too.
10. **API versioning** — Already done: every route is `/api/v1/*`, documented in `api/openapi.yaml` and `api/asyncapi.yaml`.
11. **Named enums instead of idx=0/1/2** — Still valid but low priority; `state_json.h` already ships `profileName` alongside `profileIdx`, so it's typed and self-describing — a string-only API would be a breaking change for cosmetics.
12. **Diagnostics ZIP** — Not applicable; no filesystem partition by design (`partitions.csv`), the web UI is a compiled-in string (`main/net/index_html.h`), no zip library. Item 6 covers the useful content.
13. **Full HAL abstraction** — Overkill as stated; already ~90% solved by `lib/autolee_logic/` being ESP-IDF-free. The valuable 10% is a fake behind the existing `stepper::`/`tmc5160::` namespaces — that's item 5 above.
